# 1인 수의계약 모니터 · 전북특별자치도교육청

전북특별자치도교육청이 공개하는 [계약체결현황](https://www.jbe.go.kr/open/edufine/eduCntrlist1.jbe?menuCd=DOM_000001003001009000&cntr_mthd_div_nm=1%EC%9D%B8%EC%88%98%EC%9D%98)
가운데 계약방법이 **1인수의**인 건을 모아, 현황과 확인이 필요한 건을 보여주는 비공식 도구다.
학교를 포함한 전 기관이 대상이다.

## 왜 긁어오나 — API가 없다

- 그 화면은 서버가 HTML을 통째로 그려 내려주는 JSP다. 안쪽에서 부르는 JSON 호출이 없고, 엑셀 내려받기도 없다.
- 공공데이터포털에 `전북특별자치도교육청_통합홈페이지_정보공개`(15145393)가 있지만
  **연 1회 갱신**에 컬럼이 `정보공개명·회계년도·기관명·계약(사업)명` 넷뿐이다. 금액도 상대자도 없고 학교도 빠진다.
- 대신 검색조건이 전부 GET 파라미터고, 화면에 없는 **`pageUnit`** 파라미터가 먹힌다.
  기본 10건짜리 쪽을 1000건으로 늘려서, 연간 5만~10만 건을 50~100번 요청으로 받는다.

## 폴더

```
scripts/collect.py     전수 수집 (연도별, 50~100요청)
scripts/update.py      새로 올라온 것만 (보통 1~2요청)
public/data/           contracts_<연도>.json · inst_kinds.json · index.json — 화면이 그대로 읽는다
src/                   화면 (Vite + React 19 + TypeScript + Tailwind v4, KRDS 토큰)
```

## 쓰는 법

```bash
python scripts/collect.py            # 2023~2026 전수 수집 (25분쯤)
python scripts/collect.py 2026       # 한 해만

npm install
npm run dev                          # http://127.0.0.1:3100

python scripts/update.py             # 이후 갱신은 이것만 (올해)
```

`update.py`는 목록 앞쪽부터 훑다가 이미 가진 건이 300건 연달아 나오면 멈춘다.
새로 올라온 계약을 화면에 찍어 주므로, 매일 돌리면 그 자체가 알림 노릇을 한다.
사이트 표기 건수와 어긋나기 시작하면 `collect.py`로 그 해를 다시 받으면 된다.

## 저장 형식

기관명·상대자명이 심하게 반복되므로 사전으로 빼고 행은 번호로만 참조한다.
객체 배열로 두면 파일이 서너 배가 된다.

```json
{
  "year": 2026, "site_total": 49393, "collected": 49393,
  "collected_at": "2026-09-07T11:20:03+09:00",
  "cols": ["seq", "inst", "name", "date", "amount", "partner"],
  "insts": ["이리백제초등학교", "…"],
  "partners": ["합굿마을 문화생산자협동조합", "…"],
  "rows": [["104900829", 0, "…행사 품의", "2026-09-07", 2000000, 0]]
}
```

## 판정 규칙 — 결과는 '확인이 필요한 후보'다

`src/lib/rules.ts` 한 곳에 모여 있다. **공개 목록에 있는 값(기관·상대자·금액·일자)만으로** 계산한다.

**반복 수의계약** — 한 기관이 같은 업체와, **건당** 계약금액이 기준(기본 1천만원) 이상인 계약을
한 회계연도에 기준 횟수(기본 2회) 이상 맺은 경우.

- 기준은 **건당 금액**이다. 묶음 합계가 아니다 — 합계로 세면 소액 계약이 여럿 쌓여도 걸려서
  정작 봐야 할 건이 묻힌다.
- 제한이 **연 단위**로 걸리므로 회계연도 전체가 기본이다.
- `기간 좁히기`(90/30/7일·같은 날)는 그 안에 붙어 있는 계약끼리만 세어 **한 사업을 나눠 맺은 것처럼
  보이는 건**을 훑는 보조 렌즈다. 연 단위 제한 판정이 아니라는 것을 화면에도 적어 두었다.

## 기관분류구분 — 이름으로 추측하지 않는다

`시도교육청(화면에는 '본청')·교육지원청·직속기관·학교` 네 가지로 거를 수 있다.

이 값은 **목록 화면에 없다.** 검색폼의 `inst_clss_div` 파라미터는 서버가 무시하고 `schoolIn` 만 먹으므로
검색으로도 못 가른다. 상세 화면에는 있지만 계약 건마다 열면 33만 번이다.

그래서 **기관마다 한 번만** 묻는다. 계약기관은 4년 통틀어 900곳 남짓이고 이름이 바뀌지 않으므로,
대표 계약 하나를 열어 분류를 알아내 `public/data/inst_kinds.json` 에 적어 둔다. 그다음부터는
새로 나타난 기관만 채운다(`collect.resolve_kinds()`).

이름으로 추측하지 않는 이유는 간단하다 — `군산영어체험학습센터`는 **직속기관**이고
`군산가람유치원`은 **학교**다. 이름만 봐서는 못 가른다.

한계를 화면에도 적어 두었다.

- 계약 근거 조항·예정금액·목적물 구분은 **상세 화면에만** 있다. 전수로 받으려면 건당 요청이라
  33만 번이 되어 판정에 넣지 않았다. 각 행의 '원문' 링크로 확인한다.
- 상대자는 사업자등록번호가 공개되지 않아 **이름으로만** 맞춘다. `주식회사·(주)·재단법인` 같은
  법인 형태 표기를 떼고 같으면 한 곳으로 묶으므로, 이름이 비슷한 다른 업체가 묶이거나
  상호를 바꾼 같은 업체가 갈릴 수 있다.
- **회계연도와 계약연도는 다르다.** 2026 회계연도 파일에도 2025년 12월 계약이 250건쯤 들어 있다.
  월별 추이는 계약일자의 실제 연·월로 그리고, 연도 비교는 두 해가 같은 건만 쓴다.

## 공유 — GitHub Pages

부서 직원이 주소만 열면 보는 화면이다. 저장소는 공개, 배포는 GitHub Actions 가 한다.

**처음 한 번**

1. 깃허브에 저장소를 만든다(`jbe-single-bid-monitor`, Public).
2. `Settings > Pages > Build and deployment > Source` 를 **GitHub Actions** 로 바꾼다.
3. 첫 배포는 `Actions > 수집 및 배포 > Run workflow` 로 손수 돌린다.

**그 다음부터**

`.github/workflows/update.yml` 이 **매일 05:00(KST)** 에 **새로 올라온 계약만** 받아
화면을 짓고 Pages 에 올린다. 이미 받은 건은 다시 받지 않는다 — 보통 2요청, 10초면 끝난다.

받은 자료는 **저장소에 커밋하지 않는다.** 올해 파일이 5~10MB라 매일 커밋하면 한 해에 2GB가 쌓인다.
그런데 커밋을 안 하면 러너가 매일 빈손으로 시작해 전수 수집을 하게 되므로,
**어제 결과를 Actions 캐시로 물려준다.** 캐시는 깃 이력에 남지 않아 저장소가 안 커진다.

| 상황 | 하는 일 |
|---|---|
| 캐시 있음 (보통) | 목록 앞쪽만 훑어 새 건만 받는다 — 2요청 |
| 캐시 없음 (첫 실행·오래 쉼) | 그 해를 전수로 받는다 — 50요청 |
| 따라잡기 실패 | 사이트 표기 건수와 어긋난 걸 보고 스스로 전수 수집한다 |

어느 경우든 결과가 사이트와 맞는다. 지난 연도 파일은 거의 안 바뀌므로 저장소에 한 번 넣어 둔 걸 그대로 쓴다.

**대신 매일 `public/data/index.json`(500바이트) 하나만 커밋한다.** 저장소에 60일 동안 활동이 없으면
깃허브가 예약 실행을 자동으로 꺼버리기 때문이다. 큰 자료는 그대로 두고 연도별 건수만 올리므로
이력은 한 해에 0.2MB쯤 늘어난다. 덤으로 날짜별 건수 기록이 깃 이력에 남는다.

> 깃허브 예약 실행은 몇 시간씩 밀리는 일이 있다.
> 정시성이 필요하면 `Run workflow` 를 손으로 누르거나 자체 호스팅 러너로 옮긴다.
> 참고로 `jbe.go.kr` 은 데이터센터 IP를 막지 않는다 — 해외 클라우드에서 340회 넘게 받아 확인했다.

## 암호 — 자물쇠가 아니라 가림막이다

**화면 전체가 암호로 가려져 있다.** 기본 암호의 SHA-256 해시가 `src/components/Gate.tsx` 에 박혀 있다.
바꾸려면 `Settings > Secrets and variables > Actions` 에 `GATE_HASH`(새 암호의 SHA-256 16진값)를
넣고 다시 배포하면 그 값이 이긴다.

```bash
python -c "import hashlib,getpass;print(hashlib.sha256(getpass.getpass('암호: ').encode()).hexdigest())"
```

**다만 이건 자물쇠가 아니다.** 정적 페이지라 암호 확인이 브라우저 안에서 일어나고, 확인에 쓰는 해시는
어차피 배포된 자바스크립트에 들어간다. 게다가 원자료 `data/*.json` 은 주소만 알면 암호 없이도 받을 수 있다.
막으려는 것은 '주소를 우연히 연 사람이 바로 들여다보는 일'이지 자료 유출이 아니다.

진짜 접근통제가 필요하면 Cloudflare Access(무료 50명)를 Pages 앞에 세워 지정한 메일 주소만
통과시키는 쪽이 맞다. 그때는 이 암호 가림막을 빼도 된다.

## 제외 키워드

계약명이나 계약상대자에 특정 말이 들어간 건을 화면에서 뺀다. 두 벌이 있다.

- **공용** — `public/data/exclude_keywords.json` 의 `keywords` 배열. 모두에게 같이 적용된다.
  화면에서는 못 고친다(정적 페이지라 저장할 자리가 없다). 고친 뒤 다시 배포해야 반영된다.
- **개인** — `설정` 탭에서 넣는다. 넣는 즉시 적용되고 브라우저에 남아 컴퓨터를 껐다 켜도 그대로다.
  다른 PC·다른 브라우저·시크릿 모드에는 안 넘어간다.

뺀 건을 말없이 숨기지 않는다 — 화면 위쪽에 `제외 키워드로 N건 뺌` 을 늘 같이 보여주고, 누르면 설정으로 간다.

## 엑셀 내려받기

모든 목록에 내려받기 단추가 있다. **화면에 몇 줄만 펼쳐져 있어도 파일에는 걸린 것 전부**가 담긴다.

- `현황` — 집계표(월별·금액대·기관분류), 계약 전체
- `반복 수의계약` — 조합 요약, 해당 계약 전체, 카드별 계약
- `기관·업체 조회` — 집계 목록, 고른 기관·업체의 계약
- `최근 계약` — 검색에 걸린 계약

형식은 **UTF-8 BOM 을 붙인 CSV** 다. 엑셀이 바로 열고, BOM 이 없으면 한글이 통째로 깨진다.

못 받았을 때 가짜가 진짜처럼 보이는 것이 가장 나쁘다.
